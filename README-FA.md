# اپ دسکتاپ ویندوز — فاز ۵

اپلیکیشن ویندوزی WPF ساخته‌شده با **.NET Framework 4.8** — تنها گزینه‌ای که هم روی
**ویندوز ۷ SP1** و هم **ویندوز ۱۰** درست کار می‌کند (نسخه‌های .NET 5 به بعد دیگر از
ویندوز ۷ پشتیبانی نمی‌کنند، برای همین این انتخاب انجام شد).

## راه‌اندازی بیلد خودکار در گیت‌هاب
۱. یک ریپازیتوری جدید بسازید و **کل محتوای این پوشه (`desktop/`)** را در **ریشه‌ی همان ریپو** push کنید (یعنی پوشه‌ی `TapeKhashDesktop`، فایل `installer.iss` و `.github` باید مستقیم در ریشه‌ی ریپو باشند، نه داخل یک پوشه‌ی دیگر).
۲. با اولین push روی شاخه‌ی `main`، اکشن «Build Windows Desktop App» خودش اجرا می‌شود (روی یک ران‌ر ویندوزی، چون این برنامه فقط روی ویندوز اجرا می‌شود).
۳. بعد از پایان اجرا، در بخش **Artifacts** دو فایل می‌بینید:
   - **TapeKhashDesktop-Setup** — یک نصب‌کننده‌ی کامل (`TapeKhashDesktop-Setup.exe`) که آیکون دسکتاپ هم می‌سازد؛ همینی که برای نصب روی سیستم‌های دیگر لازم دارید.
   - **TapeKhashDesktop-raw-build** — فایل‌های خام بیلد، برای مواقعی که فقط می‌خواهید بدون نصب‌کننده اجرا کنید.
۴. روی سیستم مقصد (ویندوز ۷ یا ۱۰)، **.NET Framework 4.8** باید نصب باشد — روی ویندوز ۱۰ به‌روز معمولاً از قبل هست؛ روی ویندوز ۷ ممکن است نیاز به نصب جداگانه‌اش باشد (لینک مایکروسافت: پکیج «Microsoft .NET Framework 4.8» برای ویندوز ۷ SP1).

## تنظیم آدرس سرور
آدرس‌های پیش‌فرض در `Data/Session.cs`:
```
BaseUrl:     https://mahroch.ir/tape-khash-api/index.php
FileSyncUrl: https://mahroch.ir/file/sync.php
```
اگر دامنه یا نام پوشه‌ها را عوض کردید، در صفحه‌ی ورود بخش «تنظیمات آدرس سرور» را باز کنید و آدرس API را عوض کنید (آدرس sync در حال حاضر فقط از کد قابل تغییر است — اگر لازم شد در قدم بعد یک فیلد تنظیمات برایش اضافه می‌کنم).

## نصب فایل sync.php روی هاست (برای همگام‌سازی)
فایل `backend/server-file/sync.php` (در بستهٔ بک‌اند) را کنار `search.php` در `public_html/file/` آپلود کنید. این فایل:
- فقط داخل پوشه‌ی `file/` کار می‌کند (خروج از آن، مثل `../`، همیشه رد می‌شود)
- آپلود فایل‌های اجراشدنی (php و غیره) را مسدود می‌کند
- **هیچ اکشن حذفی ندارد** — یعنی همگام‌سازی هرگز چیزی را از هاست شما پاک نمی‌کند؛ فقط فایل‌های جدید/تغییریافته رد و بدل می‌شوند. این تصمیم عمدی بود تا کوچک‌ترین ریسکی برای فایل‌های سایت شما ایجاد نشود.

## ساختار
- `Data/Session.cs` / `Data/ApiClient.cs` — تنظیمات محلی + ارتباط با API (JSON، آپلود چندبخشی، همگام‌سازی فایل)
- `Views/LoginView`, `Views/AppSelectView` — ورود + انتخاب برنامه (دقیقاً مثل اپ اندروید)
- `Views/Tape/` — جستجو، تپه‌های من، ثبت تپه، و پنل مدیریت کامل شامل **تب «همگام‌سازی فایل‌ها»**
- `Views/Khash/` — نیروها، فاکتورها، پرداخت‌ها، سفارشات خاش (با دکمه‌های مرحله‌به‌مرحله)، گزارش‌ها

## محدودیت‌های این نسخه (صادقانه)
- من در این محیط SDK ویندوز/کامپایلر ندارم، پس این پروژه را واقعاً بیلد نکردم — نحو (syntax) هر فایل C# و XML بودن هر XAML را جداگانه بررسی کردم، ولی اولین بیلد واقعی همان اجرای GitHub Actions است. اگر خطای بیلد گرفتید، پیامش را کامل برایم بفرستید تا سریع رفعش کنم.
- همگام‌سازی فایل بر اساس هش/زمان تغییر فایل تصمیم می‌گیرد کدام طرف جدیدتر است؛ تداخل هم‌زمان دو ویرایش متفاوت روی یک فایل (نادر) به نفع جدیدتر حل می‌شود، نه با merge محتوا.
- نصب‌کننده امضای دیجیتال ندارد؛ ویندوز ممکن است هنگام اجرا هشدار SmartScreen نشان دهد («More info» → «Run anyway»).
